Pixel 4 XL 2D 人脸解锁模块正式上线 GitHub

折腾了好一阵子的 Pixel 4 XL 2D 人脸解锁模块，现在终于整理完成并上线 GitHub。源码、APK、安装说明、兼容性记录和测试报告都已经公开，感兴趣的朋友可以直接下载体验，也欢迎一起改进。

项目地址：Vickylines/Pixel4xl-2DFaceUnlock
最新版本：Pixel2DFaceUnlock v0.8.0

为什么做这个模块

Pixel 4 XL 原本配备红外与深度硬件，但在一些较新的第三方 ROM 中，原生 3D 人脸解锁并不能正常使用。手机本身没有指纹识别，一旦失去原生面容功能，日常点亮屏幕之后就只能频繁输入 PIN 或密码。

这个项目的目标很直接：在已经 Root、安装了 LSPosed，并使用 Pixel／AOSP 类 SystemUI 的设备上，通过普通前置摄像头补上一套方便日常使用的 2D 人脸解锁。

它现在能做什么

模块通过 LSPosed 注入 com.android.systemui，识别过程不会显示自拍预览，解锁动画也直接融入原生锁屏。

  • 在普通锁屏页面识别成功后，小锁会变为解锁状态，向上滑动即可进入桌面。
  • 已经进入 PIN 或密码页面时，识别成功可以直接完成当前解锁。
  • 支持“面容光环”和“灵动岛”两种锁屏动画。
  • 重启后的第一次解锁、锁定模式以及系统要求强认证时，仍然必须输入 PIN 或密码。
  • 模块不修改 ROM、boot、system 或 vendor 分区；停用 LSPosed 模块并重启即可恢复原来的锁屏行为。

当前版本为 v0.8.0。这一版加入了 49 区局部纹理、25 区核心区域和 7 维脸部几何的双重身份校验，继续采用多帧稳定确认，同时修复了 Android 16 下相机宿主输入层可能阻断锁屏触控的问题。

在 Pixel 4 XL（coral）、LineageOS 23.2、Android 16 的真机热启动测试中，识别中位耗时约为 354 ms。这是当前测试环境的数据，不代表所有 ROM、光线和设备都能得到相同速度。

适用范围

项目面向带可用前置摄像头的 arm64-v8a Google Pixel 设备，代码覆盖 Android 10–16（API 29–36），优先适配 Pixel 原生系统、LineageOS 及其他接近 AOSP SystemUI 的 ROM。

这里需要把“兼容”和“实测”分开说：目前完成完整真机验证的是 Pixel 4 XL + LineageOS 23.2 + Android 16。Android 10–15 已完成对应兼容编码和构建检查，但尚未在每一个版本、每一台 Pixel 上逐一验证；三星、小米、OPPO、vivo 等深度修改 SystemUI 的系统也不在支持范围内。

安装方法

安装前请确认设备已经解锁 Bootloader，Magisk Root、Zygisk 和 LSPosed 均能正常工作，并提前备份重要数据。

  1. 从 GitHub Releases 下载最新版 APK。
  2. 安装 APK；从旧版升级时直接覆盖安装，不要先卸载。
  3. 在 LSPosed 中启用“Pixel 2D 人脸解锁”，作用域只勾选“系统界面（com.android.systemui）”。
  4. 完整重启手机，先按系统要求输入一次 PIN 或密码。
  5. 打开模块，确认“LSPosed 钩子已加载”，再录入人脸并测试。

从 v0.7.x 或更早版本升级到 v0.8.0 后，需要重新录入一次，以生成新版 v3 人脸模板。更完整的步骤和排错方法请以仓库中的中文安装说明为准。

必须说明的安全边界

这个模块使用的是普通 RGB 前置摄像头，不是 Pixel 4 XL 原装的红外／深度 3D 人脸识别，也不具备 Class 3 生物识别的安全强度。高质量照片、视频或屏幕重放仍有可能绕过，因此它只适合便利解锁，不能替代 PIN、密码或强生物识别。

它不会向银行、支付、密码库等应用提供系统生物认证。当前实现没有网络权限，人脸特征保存在应用私有目录，不保存录入时的原始照片，也不会上传。

如果手机里有高价值资料，或者对失窃后的数据保护要求较高，建议不要启用 2D 人脸解锁。Root、Magisk 和 LSPosed 本身也会扩大系统改动范围，安装前请理解风险，并准备好可恢复的 boot／init_boot 镜像。

写在最后

把项目放上 GitHub，不只是为了提供一个 APK，也希望每一项兼容判断、安全限制和测试结果都能被看见。它目前还称不上“装上就适配所有 Pixel”，但至少在已经完成验证的环境里，Pixel 4 XL 又多了一种足够顺手的日常解锁方式。

欢迎提交 Issue、测试反馈或 Pull Request。尤其是 Android 10–15、其他 Pixel 型号和不同 AOSP ROM 的实测结果，会比一句简单的“支持”更有价值。
